# 运行时与星历

CalcChineseCalendar 的运行体验，核心取决于星历来源和时间参数。

## 星历来源

项目有两条计算路径：

- `BSP`：优先使用 JPL DE BSP 星历，适合更高精度场景
- `@series`：显式使用内置 VSOP87A + ELPMPP02 级数模型

当启用了默认回退策略时，程序会在找不到 BSP 的情况下自动切到内置模型，继续完成计算。

## BSP 选择机制

文档和 README 中已经定义了自动选择逻辑，当前可以先按下面的心智模型理解：

1. 先看命令行中是否显式传入 `--bsp` 或位置参数 BSP。
2. 再看配置文件 `lun_cfg.txt` 中有没有默认值。
3. 若未找到可用 BSP，则根据构建开关决定是否回退到 `@series`。

这意味着：

- 想追求确定性时，显式传入 `@series` 或具体 `.bsp` 路径
- 想减少参数输入时，把默认 BSP 写进配置文件

## 配置文件 `lun_cfg.txt`

常见用途：

- 配置默认语言
- 配置默认星历路径
- 配置交互模式的常用默认项

建议把它放在运行目录附近，并把“默认值”和“单次覆盖”分开使用：

- 默认行为写进配置
- 单次试验通过命令行覆盖

## 时间与时区

两个规则尤其重要：

- 输入时间支持 ISO 风格表达
- `--tz` 通常只影响显示文本；农历判日边界请显式使用 `--lunar-day-tz`

如果你的业务是“当天黄历”“跨午夜事件”“时区敏感查询”，建议显式传入时区，不要依赖环境默认值。

## 推荐实践

- 开发阶段优先用 `@series` 跑通流程
- 准备发布或做严肃比对时，再换成固定版本的 `.bsp`
- 对外接口中始终显式记录 `ephem` 和时区来源
- 把高频默认项固化在 `lun_cfg.txt`，把实验性参数留给命令行
